# Project reflection

I used Strands SDK with AgentCore Gateway and MCP to separate the agent's reasoning from the implementation of its business tools. Nova 2 Lite can select an appropriate capability, while the order and refund handlers retain explicit interfaces. This made the integration boundaries important: order lookup receives API Gateway proxy events, whereas the refund Lambda receives direct Gateway tool arguments. Keeping those contracts distinct makes the system easier to understand and provides a clear place to enforce business rules independently of model instructions.

The deployment challenge involved Python 3.13, Linux ARM64, and native dependency compatibility. A dependency that works on a local development machine is not automatically suitable for the Runtime environment. The completed dependency configuration pins lazy-object-proxy to version 1.12.0. The lockfile includes a compatible CPython 3.13 ARM64 Linux wheel, and the original deployment dependency archive contains the matching compiled extension. These artifacts support the compatibility resolution. I have not retained the original failure transcript, so I cannot substantiate a specific earlier failing version or error message. This experience reinforced the value of checking target-platform artifacts and retaining build evidence, rather than relying only on local installation success.

The project also showed why functional success and production readiness need separate evaluation. Cross-session memory recall succeeded after retry, which reflects asynchronous extraction rather than guaranteed immediate availability. The correct loyalty breakdown likewise does not independently prove sandbox execution without tool-level evidence. For production, I would scope IAM permissions by integration, verify customer identity before selecting a memory namespace or order, and replace the educational unsigned Gateway connection with authenticated access. Refunds would require ownership checks, durable state, idempotency, and approval controls. Customer-memory isolation and careful log retention would be essential before introducing real personal information.
